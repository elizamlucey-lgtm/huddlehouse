## 2. Let's Start a Project!

**Pip:** "Our team needs to launch a new product feature. Where do we start?"

**Nova:** "Let's create a project!"

A project is simply a place where a team organizes a piece of work.

Think about planning a birthday party.

You might need to:

- Choose a date
- Send invitations
- Buy decorations
- Prepare food
- Make sure everything is ready

A team project works the same way. It breaks a big goal into smaller jobs.

### Our fictional project

Let's pretend the Huddlehouse team is launching a new feature called **Team Calendar**.

Here's how the team might organize the work:

| Task | Who's responsible? | Status |
|---|---|---|
| Design the calendar | Design Team | In progress |
| Build the calendar | Engineering | Not started |
| Write help documentation | Documentation | Not started |
| Test the feature | QA Team | Not started |

**Pip:** "Oh! So instead of everyone trying to remember what needs to happen, we can organize the work in one place?"

**Nova:** "Exactly!"

<blockquote>
  **Remember:** Projects help teams organize goals, tasks, responsibilities, and progress.
</blockquote>

## 3. Now, Let's Talk About Huddles

**Pip:** "Okay, but what if I have a question for the design team?"

**Nova:** "That's where Huddle comes in!"

A Huddle is a place for conversations, updates, and teamwork.

Imagine you're working on the Team Calendar project.

The designer might post:

> "I've finished the first calendar design. Can someone review it?"

An engineer might respond:

> "Looks good! I have one question about the monthly view."

The documentation writer might say:

> "I'll start preparing the help article using this design."

Everyone can share updates and coordinate their work.

### When should you use Huddle?

Use Huddle when you need to:

- Ask a teammate a question
- Share a project update
- Discuss an idea
- Coordinate next steps
- Get feedback from others

**Pip:** "So Huddle is where we talk about the work, not necessarily where we store every important document?"

**Nova:** "You got it!"

## 4. Where Do We Keep Important Information?

**Pip:** "We talked about the new calendar design in Huddle. But what happens when someone needs to find those decisions next month?"

**Nova:** "That's why we have the Library!"

The Library is a shared place to store useful information.

Think of it like a giant team notebook.

You might keep:

- Product guides
- How-to instructions
- Team procedures
- Frequently asked questions
- Project decisions
- Technical documentation

For example, after the Team Calendar feature launches, the documentation writer might create a guide explaining how to use it.

That guide belongs in the Library.

**Pip:** "So if I join the company next month, I can find the guide instead of asking everyone to explain it again?"

**Nova:** "Exactly! That's the whole point."

## 6. A Few Common Mistakes to Avoid

Even experienced teams sometimes make collaboration mistakes.

Here are a few things to watch out for:

| Common mistake | A better approach |
|---|---|
| Keeping important decisions in private messages | Share important decisions where the team can find them |
| Creating duplicate documents | Check the Library before creating something new |
| Forgetting to update project tasks | Keep task status current |
| Discussing work without recording the outcome | Document important decisions |
| Leaving teammates out of important updates | Share relevant updates with the right people |

**Pip:** "So good teamwork isn't just about talking. It's also about making sure everyone can find the information they need."

**Nova:** "Now you're thinking like a Huddlehouse teammate!"
